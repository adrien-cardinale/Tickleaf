Encryption and sync

Each device keeps its own SQLite database with all your tasks. The server only relays encrypted blobs and never sees anything in clear text.

Keys

  • Master key: 32 random bytes created on the device. It is shown as a recovery key in Crockford base32, in groups of four characters, with a checksum that catches typos. The master key never leaves the device.
  • Derived values (HKDF-SHA-256): a public user id, an auth secret and an AES-256-GCM key.
  • Sealed blobs: each entry is encrypted with a random 12-byte IV, prefixed by a format version, with the user id bound as additional data.
  • Authentication: Authorization: Bearer <userId>.<secret>. The server stores only the SHA-256 hash of the secret. No password, no session.

Local storage

The database runs in memory with sql.js. It is saved encrypted in IndexedDB 500 ms after each change and when the page closes, one entry per account. The browser may clear this storage: site data cleanup, private browsing, storage pressure, or long inactivity on Safari. With a server, your tasks come back on another device with the recovery key.

Synchronization

The server is a blind, ordered log. Clients do the merging.

  1. Pull: the client reads the log from its cursor, decrypts each entry and applies its rows. An unreadable entry stops the sync without moving the cursor.
  2. Push: local changes not yet sent go out in batches of 200, each sealed and appended to the log.
  3. Conflicts: the most recent change wins. Deletions are soft, so they reach every device.

Sync runs at startup, every 5 minutes, 5 seconds after each change, when the app comes back to the foreground, when the network comes back, and on demand from the sidebar.
